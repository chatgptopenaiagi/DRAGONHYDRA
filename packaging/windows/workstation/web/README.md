# Private workstation web stack

This payload adds the Joomla sports workspace and administration runtime to the unified Windows x64
workstation installer. It contains a private Apache 2.4.65, PHP 8.4.27 TS VS17 x64,
MariaDB 10.11.16 and a pristine Joomla 6.2.0 distribution. Existing XAMPP services,
sites, configuration and data are never copied or changed. The Python kernel
continues to own sports data in its selected SQLite store. A reserved MariaDB core
schema is created for later validated migration; it is not an active second writer.

The runtime is assembled by `prepare_payload.py` from explicit local inputs. It
verifies the pinned PHP/Joomla archive hashes, copies only named Apache/MariaDB
runtime files and notices, checks AMD64 PE imports and produces a file/hash
inventory in `payload-manifest.json`. Input binaries are not proof of clean-machine
compatibility; the complete installer still needs its own installation evidence.

## Supervisor contract

Immutable payload is `<install_root>/web/`. Mutable data is `<state_root>/site`,
`mysql-data`, `web-config`, `web-logs`, `web-temp` and `web-sessions`. The supervisor
must protect the entire state directory for its service identity and authorized
administrators before writing configuration. The CLI hook is outside the web root.

The private JSON configuration contains `install_root`, `state_root`, `web_port`,
`database_port`, `api_port`, `api_base`, `bridge_secret_path`, `root_password`,
`db_name`, `db_user`, `db_password`, `core_db_name`, `core_db_user`,
`core_db_password`, `admin_user`, `admin_password`, `admin_email`, `site_name`.
`api_base` selects `http://127.0.0.1:<api_port>/dragon/api/v1`. Credentials are
generated by the supervisor and retained only in protected mutable state.

Run only the installed private PHP:

```powershell
& "$InstallRoot\web\php\php.exe" -c "$StateRoot\web-config\php.ini" `
  "$InstallRoot\web\manage.php" "$PrivateConfigPath" prepare
```

`prepare` needs no database connection. It creates the pristine site once and
writes `web-config/php.ini`, `httpd.conf`, and `my.ini`. It never restores a removed
Joomla installation directory during repair.

For every child process, prepend the installed `web/php`, `web/apache/bin` and
`web/mariadb/bin` directories to that child's `PATH` only. This enables private
extension DLL resolution without altering the machine environment.

For a fresh data directory only, initialize with the bundled
`web/mariadb/bin/mysql_install_db.exe --datadir=<state_root>/mysql-data
--port=<database_port> --silent`. Start MariaDB using
`mariadbd.exe --defaults-file=<state_root>/web-config/my.ini --console`. The
supervisor must check actual bind ownership, use only the selected loopback port,
and call `provision` immediately after readiness. Empty-root bootstrap is accepted
only with the fresh-private-datadir marker created by `prepare`. Provisioning sets
the supplied root password immediately and removes anonymous identities, then
creates separate schema users. Repair does not rotate existing credentials.

After database readiness, call the same PHP hook with `provision`, `install`, and
`configure`. `install` creates Joomla once, installs or updates the extension only
when its package hash changes, and retains existing extension settings.
`configure` merges the selected API and identity-bridge references into those
settings without creating demonstration accounts or modifying default ACLs.
It then invokes the installed component's idempotent `FrontendSetup::apply()` through
the matching Joomla CLI bootstrap. Later repair therefore retains the native
workspace Home and child-template assignment rather than restoring sample content.
The `_configure-frontend` child performs only Joomla presentation setup and does not
read bridge contents, rotate credentials, create sports records or activate providers.

The current provisioner requires the frontend-capable extension package with its
Cassiopeia child template. `Build-WebPayload.ps1` defaults to the canonical package
version declared in `server/joomla/pkg_dragonhydra.xml`; build it with
`scripts/build_joomla.py` first. `prepare_payload.py` validates the actual package,
component/site files and child-template manifest, then records their version/hash in
the web payload manifest. A historical administrator-only ZIP is not silently
substituted for the current workspace package.

To prepare only the affected presentation/provisioning inputs while reusing an
already verified immutable web runtime, use a **new** project-local build directory:

```powershell
& '.\runtime\server-env\Scripts\python.exe' `
  '.\packaging\windows\workstation\web\prepare_payload.py' `
  --reuse-payload '<verified-baseline-web-payload>' `
  --destination '<project>\build\<new-web-payload>' `
  --extension '<built-pkg_dragonhydra-0.4.1-dev.2.zip>'
```

This verifies every original payload file and rejects unexpected files/links before
copying. It replaces only `extension.zip`, `manage.php` and this README, rehashes the
new tree, and preserves the original runtime provenance. It changes no installed
site or service and rebuilds no Python server/client. The resulting manifest is a
payload-integrity claim, not fresh installation or clean-machine acceptance.

Fresh `Build-Workstation.ps1` builds now select the same current frontend package;
`-JoomlaPackagePath` supplies an explicit matching builder-manifest/hash-verified
alternative. For a new isolated copy of verified staging, `-RepackageOnly` with that
parameter refreshes the extension and matching hook and records
`joomla_frontend_override`. A repackage without a new package retains its actual old
identity; it cannot claim a frontend it does not contain. Refreshing the current hook
over a pre-frontend baseline requires the matching package. Historical installers,
release assets and independently installed sites are not rewritten by source changes.

Start Apache using `web/apache/bin/httpd.exe -d <install_root>/web/apache -f
<state_root>/web-config/httpd.conf`; first validate it with the same arguments plus
`-t`. Both Apache and MariaDB bind to `127.0.0.1` only. The private Joomla origin
forwards `/dragon/` to the selected local kernel; normal kernel authentication
still applies. Public access belongs to the separately restricted gateway.

`status` returns bounded JSON with versions, URLs, enabled extension identity and
configuration hashes. `shutdown` asks only the selected authenticated MariaDB
instance to shut down. The integration supervisor owns Apache termination, process
tracking, startup deadlines, retry limits, port selection and service lifecycle.
The hook never stops or discovers unrelated services. Each action exits nonzero on
failure and reports a machine-readable error code without printing vendor
exception messages or passwords.

Reference compatibility: [Joomla requirements](https://manual.joomla.org/docs/get-started/technical-requirements/)
and [PHP's Windows Apache handler instructions](https://www.php.net/manual/en/install.windows.apache2.php).
The Apache handler requires thread-safe PHP; the package deliberately uses that
variant and carries required upstream notices.
