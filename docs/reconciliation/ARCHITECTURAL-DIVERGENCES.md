# Architectural divergences

See the [tested theory comparison](../architecture/THEORY-COMPARISON.md).

The original eighteenth role inventory and CORE NEXT's six engines/twelve
supporting bindings are different contracts:17 roles map directly; original
evidence_store is represented through retained evidence/storage operations while
CORE NEXT adds packaging_recovery. A matching count does not establish matching
IDs, capability proof or operational semantics.

CORE NEXT separates cached passive reads from explicit bounded checks. The
original serializer calculates passive metadata on read. CORE NEXT's lifecycle
and installed identity are the selected product authority. Reintroducing the
original registry would produce competing observations and ambiguous clocks.

The nested foundation's DuckDB analytical schema and Qt shell are intentionally
separate research. Its result_available_at contract is useful, but caller-supplied
availability is not proof of actual earlier knowledge. Existing CORE NEXT source-
scoped identity, immutable receipts, SQLite storage and Tauri client remain the
release implementation. No duplicate authoritative calculations were recovered
among the25 byte-identical selected scientific/provider files.
