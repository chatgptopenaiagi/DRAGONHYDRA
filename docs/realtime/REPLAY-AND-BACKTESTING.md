# Virtual time, replay and evaluation

The standard fictional scenario includes kickoff, routine possession and shot, duplicate delivery, goal, equalizer, halftime/resumption, red card, substitution, late goal cancellation, card correction, stoppage, disconnect/reconnect and a delayed final whistle. Its fixed epoch is 2035-01-01, with fictional teams and explicit event/receipt timestamps. It is not a reconstruction of an actual match.

`POST /dragon/api/v1/realtime/scenarios` creates a seeded scenario. `scenario_id: standard` with the constant world selects the scripted acceptance match; `scenario_id: universe` selects the seeded generator for any of the five worlds, including `clock_sensitive`. Direct replay controls support speed 0.1–100; the authenticated API/UI support integer speeds 1–100. Controls accept `step`, `start`, `pause` and `resume` with bounded step counts. The server advances virtual time; passive browser polling does not. Pause interrupts the playback wait. Retained PLAYING state becomes PAUSED after process restart. Repeating the same seed/configuration/input prefix produces equivalent numerical forecast distributions; processing latency is deliberately not part of numerical equivalence.

`POST /realtime/matches/{id}/branches` uses an accepted **state revision**, branch name, seed and world. It copies only that prefix into a new match. It retimes the fictional continuation after the prefix's receipt cutoff, preserves known stoppage endpoints and inserts explicit resumption where needed. The parent events and historical forecast bytes remain unchanged. The dashboard's rewind is this immutable branch operation, not a deletion.

The generic evaluator requires synthetic provenance, exact target/horizon agreement and prediction availability strictly before the relevant outcome. It rejects future training/cutoff leakage and ambiguous duplicate episodes. A numeric playing-time target with an interrupted/unknown clock mapping is not scored against a later unrelated wall-time outcome. Zero probability assigned to the realized class produces an infinite-loss status, not a secretly clipped metric.

The scenario evaluator predeclares one last available forecast by minute thirty per finished virtual match. It does not score the final observed point mass or count all correlated revisions as independent matches. Brier score, log loss, reliability bins, coverage and limitations remain inspectable. Baseline A and virtual-reasoner B use identical probability vectors: their predictive-quality difference must be zero. Working explanations and extra tool calculations are not reported as a forecasting improvement.

The multi-world relevance experiment is a separate synthetic held-out study. It can learn different useful features under different invented laws, but it provides no real-world accuracy or external OpenAI acceptance evidence. Historical dev.5 acceptance receipts, retained databases and provider settings are never replayed or modified by these operations.
