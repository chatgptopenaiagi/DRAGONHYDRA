# GENESIS-6 virtual relevance laboratory

The new capability investigates which information improves a prediction, for which target and at which time. The isolated component is `0.1.0-virtual-experimental`, derived from the preserved CORE NEXT source checkpoint `db8414ff6a08bd0c85310564771475e71d00e8a4`. It is a development research package, not a replacement for the published dev.8 installation.

Every sporting event, team, player, provider, history, outcome and credential in this lane is fictional. `REPLAY` and `DEMONSTRATION` both mean synthetic input here. `LIVE` is rejected. The inert virtual API credential is a test object; it provides no external access. No OpenAI account, real sporting dataset or installed profile is required.

## Composition

`events` validates small versioned observations. `store` owns a new SQLite event journal and immutable state, decision, forecast, analysis and experiment evidence. `replay` controls virtual time. `service` composes model-dependency relevance decisions, residual-time probability calculation, change detection and bounded investigation. `models` reuses the existing pure Poisson primitive; the retained-data forecasting workflow is never invoked. `worlds` generates different fictional laws and measures feature utility. `evaluation` scores matured predictions without future-label leakage. `bridge` provides a virtual Responses-compatible transport and nine working read/computation tools.

The optional `realtime_research` kernel extension exposes authenticated additive API routes. The existing registry has eighteen modules when this capability is disabled and nineteen when enabled. The web research view reuses the desktop web resources and existing session mechanism. Default product behavior remains separate. Its virtual launcher disables acquisition, legacy mutation, existing credential inspection and the legacy AI observer, and supplies an empty source directory and fresh marked runtime. Status GETs neither create scenarios nor advance time.

The launcher binds only a requested loopback port, refuses forbidden historical ports, takes an exclusive process lock and never installs a service. The new state must be beneath this lane's `runtime` directory with a matching ownership marker. Existing nonempty directories, reparse paths, installed profiles and foreign databases are rejected before adoption. This is ordinary task isolation, not a new workspace-guard subsystem.

## Revisions and recovery

Each accepted fact advances a per-match state revision under a lock. Forecast publication checks that revision atomically, so an obsolete computation cannot become current. A correction reconciles the accepted event prefix, appends a new state and records invalidation links; previous predictions remain immutable. A pending reasoning intent is persisted before investigation. An unresolved intent is not automatically retried after restart. Budgets and completed analyses are reconstructed from local evidence.

Restart pauses an active replay. Rewind and fork create a new virtual match from an accepted prefix and a separately seeded continuation. They never delete the parent or rewrite its predictions. A virtual pause requires an explicit resumption event. A known second-half stoppage endpoint is retained when constructing the continuation. Continuations use regulation generators; they do not establish the fidelity of real stoppage-time dynamics.

## Scientific boundaries

The dependency gate is a deterministic processing policy, not an estimated information value. Held-out experiments separately estimate `R(X,Y,T)` as a proper-loss reduction. Mathematical coherence, simulated held-out utility, external model connectivity and real predictive accuracy are different acceptance scopes. An explanation cannot override a probability vector. A configurable-rate spread is sensitivity analysis, not disagreement between independently trained models. Synthetic evaluation never establishes real-world calibration.
