# Optional retained context in Analysis

2026-10-31. The exact context reader and package/3 core have passed isolated acceptance. This API/UI increment is implemented in source: 14 new API tests, full 548-test source regression (121.805s) and eight Edge browser groups passed. Browser selections were explicitly synthetic, not Qwen inference. Evidence is under `build/connections/context-ai-api-20261031` and `build/connections/sports-package-3-20261031/browser-r2`; browser-r1's verifier URL-normalization failure is preserved. This source acceptance does not change the completed A5-r2 installer and Linux evidence.

Keep the existing actions and defaults on `sports-evidence-package/2`. Explicit secondary actions are visible only when the retained StatsBomb context response is `available`, has a verified `context_record_id`, and its parent equals the displayed match evidence. The labels are **Use local model with source counts** and **Export package with source counts**. Explain that these add retained event-row and squad-entry counts, not official match statistics or predictions. Opening Analysis must neither acquire provider data nor start inference. Keep context download/refresh as the existing separate admin action.

`GET /matches/{match_id}/analysis-package?context_record_id=source_context:<64 lowercase hex>` calls `local_ai.build_context_package`. An absent query keeps the existing package/2 constructor and bytes. `POST /matches/{match_id}/local-explanations` accepts either `{}` for package/2 or `{"context_record_id":"source_context:<64 lowercase hex>"}` for package/3. No client package, endpoint, key, model, count, parser version or evidence alias is accepted. Reject unknown body fields and explicit null, empty, boolean, numeric, object, array or malformed IDs with the existing 422 envelope. Keep router authentication and existing 409 `LocalAIError` responses. A missing or mismatched explicit context creates no job and never silently selects package/2 or another context.

Freeze the selected C1 ID when the user chooses the action. Do not look up a newer head before submitting it. Construction verifies that its parent is current once; the queued worker subsequently reconstructs the exact E1+C1 package and does not consult a newer match or context head. A changed current parent can reject a new submission while the original queued job remains valid. Unavailable, pending, stale-parent and failed context reads leave the ordinary package/2 controls usable, with a small status message rather than zero counts or an automatic provider download.

Use one `Idempotency-Key` per explicit context submission intent. Disable a second click before awaiting POST. Preserve the key when the submission response is uncertain, and use it for a later explicit retry; never automatically repeat POST or inference. Once a known job reaches a terminal failure, a later deliberate new attempt needs a new key. The server must check a narrow package/3 replay before rebuilding against current data: same owner, key, `local_explanation` kind, package/3 schema, match ID and C1 ID return the original job even after a newer parent or selected raw-data loss. Another kind, match, schema or C1 with that key conflicts. Validate key length before lookup and retain `Jobs.submit` as the final transaction/race gate. Existing package/2 replay behavior stays unchanged.

Use the existing parent and two acquisition metadata URLs in accepted context-fact citations. Carry the explicit context ID/hash, parent ID, role and each document's original capture clock; do not substitute the parent match-list clock. E1-only selections still cite only E1, while the full input manifest records E1, C1 and both document IDs. The existing mutable `/matches/{id}/source-context` route must not be presented as an immutable C1 citation. A new exact-record GET is unnecessary for this unit. A later authenticated route could call `source_context.by_id` directly and return a sanitized verified record; it must remain independent of current-parent/head selection and expose neither private paths nor raw bodies.

The Analysis opt-in consumes the compact package/3 counts, not totals derived from paginated event rows. Keep `/source-context` and `/source-events?offset=&limit=` response shapes, limits and source-native missing fields unchanged. Do not silently pin those current-view routes to the Analysis choice. If an exact-context event preview is later added, it needs an explicit context selector and page metadata bound to that same ID; current-head pagination cannot stand in for an immutable citation.

Acceptance gates for this increment:

- Authentication, strict selectors and errors: unauthenticated requests return 401; invalid selectors/unknown body fields return 422; unavailable/mismatched contexts return 409 without a job, settings decryption, provider request or inference.
- Default compatibility: absent query and `{}` retain package/2 bytes/hash, grammar, deterministic Explain and local fallback, even when verified context exists. No optional tables are initialized by reads in a sixteen-table state.
- Explicit package/3: GET and queued POST contain the same verified package; selected counts, IDs, hashes, clocks, role URLs and parent match exactly. No full event arrays, squads, private paths or credentials enter the compact package.
- Durable execution: a validated inference stub selects a context fact and returns the parent plus two role-labelled document citations and full manifest; an unconfigured runtime returns the labelled deterministic E1 fallback. Selected grounding failure occurs before runtime settings/inference.
- Replay and isolation: same owner/key/match/C1 returns the original job after parent changes or raw loss; changed C1/match/kind conflicts; another owner has an independent key space; simultaneous first submissions still pass the existing final gate.
- Retention and UI: queued old E1+C1 survives later legitimate corrections or pending/corrupt tails; selected evidence loss fails without substitution. Default controls send no selector; explicit controls send the frozen C1; pending/error states send no provider POST; existing event pagination and provenance remain intact. Test the optional controls and citations in an isolated browser before any real model probe.

API ownership is limited to `api.py`, `api_contracts.py`, a narrow Jobs replay helper and new context API tests. UI and its isolated journey have separate owners. No settings, source parser, installed service, provider download, model runner or packaging refresh belongs in this increment.
