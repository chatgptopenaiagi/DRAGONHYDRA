## Implementation and future relevance

The implemented `future_relevance` package adds a private virtual observation
generator, public snapshots, quoted acquisition costs, a one-target forecasting
adapter, past-only feature extraction, category-specific ridge models, five
acquisition policies, TRAIN/VALIDATION/final-test orchestration, immutable SQLite
evidence and an authenticated additive API. The existing default eighteen-module
registry is preserved; explicit virtual replay adds module nineteen and future
relevance adds module twenty.

Supported information is possession, shots, red cards and fatigue. Targets are
goal occurrence, full-time result, next-goal side and remaining-goal count,
with supported 1/5/10/30/full-time horizons. Full-time result requires full time.
The unchanged GENESIS-6 numerical kernel computes probabilities. The new layer
selects information; neither the mock bridge nor an explanation overrides it.

Fatigue is initially unavailable for two virtual minutes. The trained policy can
estimate its later local usefulness from the earlier public state, record DEFER,
then resume with the exact original frozen model when an explicit clock advance
makes acquisition eligible. It does not inspect the hidden value early. Later
evaluation links the earlier estimate, actual cost and same-cutoff before/after
forecasts without rewriting the decision. No acquisition is a valid policy result.

The existing virtual Responses provider, nine bounded mathematical tools,
timeline, replay controls, corrections and branching remain working at
`#research`. There is no external reasoning connection or real credential.

Brier sums squared error over outcome classes; binary scores are twice scalar
binary Brier. Utility is negative Brier minus weighted acquisition and kernel-call

95% interval **[-0.002957, 0.000155]**. No advantage is established.

## Performance

The benchmark executes 100/1,000/10,000 actual decisions **per policy**:
55,500 decisions total across its three nested workloads. Aggregate times are
4.025/38.472/323.257 seconds. At 10,000, learned acquires 43 observations versus
3,395 for acquire-all, and makes 10,043 versus 13,395 kernel calls. It nevertheless
uses more decision CPU: mean latency 11.587 ms versus 2.519 ms for acquire-all and
1.596 ms for acquire-none. Reduced acquisitions did not save CPU here.

plus actual acquisition quotes. Policy inference CPU is measured separately and
not monetized; the utility metric is not a complete economic-cost model. The
benchmark excludes SQLite, HTTP and browser throughput, uses a shared warm model
and numeric caches, and includes tracing overhead. Other local verification
